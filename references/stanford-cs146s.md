## Why this resource matters

CS146S examines the transition from manually writing most software to engineering **human–coding-agent workflows**. The Fall 2026 course description focuses on using the right context and capabilities, writing executable specifications, and iteratively planning, building, evaluating, and improving software with agents.

## Topics to study selectively

| Priority | Topic | Practical question |
| --- | --- | --- |
| P0 | Spec-driven development | Can the requirement be turned into testable acceptance criteria? |
| P0 | Context engineering | Does the agent have the right constraints, source of truth, and task-specific context? |
| P0 | Agentic code review | Can a reviewer identify incorrect assumptions and regressions in generated code? |
| P0 | Security and tool boundaries | What can the agent access, change, execute, or leak? |
| P1 | Agent-ready codebases | Are interfaces, tests, documentation, and ownership easy to navigate? |
| P1 | Agent skills, MCP and tooling | When is a reusable tool or skill preferable to ad hoc prompting? |
| P2 | Parallel/background agents and software factories | When does orchestration genuinely improve throughput without weakening review? |

## Personal practice ideas (planned, not completed)

- Write a one-page specification for a small change in an existing project.
- Ask a coding agent to propose the change, then review the patch and tests manually.
- Introduce a plausible failure case; verify that the test detects it.
- Document what the agent accomplished, what needed correction, and why the change would or would not be approved.
